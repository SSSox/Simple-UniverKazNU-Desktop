# Security

## Reporting a vulnerability

Send a private report through the repository's **Security → Report a vulnerability** tab. Do not post details in public issues until a fix is out. Describe the version and variant (Modern or Legacy, x64 or x86), the steps and what should have happened. Do not send passwords, cookies or screenshots of someone else's account.

Fixes are released for the latest version only. The Legacy variant is built on Chromium 109, which gets no more security updates (see below): vulnerabilities of Chromium itself cannot be fixed in it.

## What the app does

**Works with one site only.** Automation, the saved password, session cookies and protected downloads are allowed only for the exact address `https://univer.kaznu.kz` (port 443, no login in the address). HTTP, other ports, subdomains and look-alike addresses get none of them. The rule is in `src/Univer.Desktop/Core/SitePolicy.cs`. Embedded frames from other sites get neither sign-in data nor the app's scripts.

**Does not weaken HTTPS checks.** Certificates are checked by Chromium and Windows; `ignore-certificate-errors` and "trust everything" are not used, and certificate errors are rejected. Legacy starts Chromium 109 with `disable-features=ChromeRootStoreUsed`: its built-in list of root certificates is out of date and rejects the site's current chain, so Windows certificate verification and the Windows certificate store are used instead. The chain, name and validity period are still checked.

**Stores the password encrypted.** The login and password are kept as one record, `credentials.dpapi`, encrypted with Windows DPAPI for the current user (`ProtectedData`, `CurrentUser`); the file is replaced atomically (`Core/Storage.cs`). The password is not in the sources, settings, logs or the program folder. Chromium logging is turned off.

**Signs in through the site's own form.** On `/user/login` the app fills the visible login and password fields and presses the site's button; there is no separate HTTP sign-in and no bypassing of the site's scripts. The site's re-sign-in dialog (`#auth_modal`) is confirmed with the site's own `/user/ajl` request, and the result is checked against the server's answer. If the site asks for the password of a different account, the app stops without typing the password. Attempts are limited: at most three sign-in form submissions in 10 minutes and three re-sign-ins a minute; after two rejections of the form in a row, automatic sign-in stops until the user acts. A form submission (POST) is never repeated automatically; after a network failure only the page (GET) is reloaded, with a growing pause from 5 seconds to 5 minutes.

**Confirms only two known dialogs.** With a saved sign-in the app ticks the checkbox and presses the site's button in two dialogs that block the portal after sign-in: the read notice (`#attentionSt`) and the additional agreement (`#modal_agreement`, the "прочитал договор" checkbox, `/user/setagree`). Each dialog is recognised by its exact markup and label and is confirmed once, without resubmission. The app submits or confirms no other forms, questionnaires, messages, requests or payments. The code is in `src/Univer.Desktop/Assets/univer-automation.js` and `Web/AutomationController.cs`.

**Reads pages in the background with GET only.** Notifications (`Assets/notices.js`), distance-course tasks (`Assets/course-tasks.js`) and syllabus topics for the schedule (`Assets/syllabus-tasks.js`) read pages of the same site with `fetch` and the site's cookies, GET only, with time and size limits. A response from another address, a non-HTML response or a sign-in page is discarded. Nothing is clicked or submitted.

**Gives pages no access to the computer.** There are no JavaScript objects with access to files or the system. A page can only send the app short messages (load state, sign-in and agreement results, notifications, pinned links and home tiles, "Download all", the grade summary buttons). Buttons that start work answer only a real click; the summary is accepted only from the grades page, and its picture has a size limit. The messages are accepted only from documents of the trusted site in the current session, and all but the load state only from the main document. Chromium's remote debugging port is not opened.

**Checks downloads.** Course files (UMKD) are downloaded by a separate client (`Web/DownloadService.cs`, `Web/SessionHttp.cs`): cookies are sent only to the site, at most five redirects and only within the site, only a 200 response is accepted, a sign-in page or HTML instead of a file is rejected, files are limited to 1 GB. The file name is cleaned of invalid characters and paths, an existing file is never overwritten, and an incomplete `.part` file is deleted. Files are saved to the Downloads folder and are never opened by themselves: a document or image opens only when you click it, and the app never starts EXE, CMD or other executable files.

**Shows files without their programs.** The viewer for DOC, DOCX, XLS, XLSX, PPT, PPTX, HTML and text builds its own markup from the file contents (`Core/*Html.cs`, `Core/HtmlPreview.cs`). The viewer page is served with the CSP rule `default-src 'none'`: no scripts, frames or network. XML is read without DTD and external entities, with limits on size and depth. HTML is rebuilt from an allow-list: scripts, styles, forms, handlers and external images are removed. PDF is shown by Mozilla PDF.js from the program folder.

**Opens links to other sites in a separate panel.** Links to study sites (`http`/`https`, a named host without a login in the address) open in a panel over the workspace (`UI/WebPanel.cs`, `Web/WebHandlers.cs`). The panel has its own browser profile: cookies and cache of other sites are kept apart, and Univer cookies never get there. Only your own click returns from the panel to a Univer page, never a redirect; a new window or tab from the panel is checked the same way. Sign-out, language change, account and read-notice addresses never open from the panel (`WebLinks.HandBack`), and an empty pop-up is refused. A certificate error cancels the load, and a site's password prompt is refused. Files downloaded in the panel go to Downloads under the same naming rules; programs and scripts are not downloaded. The "Open links in an external browser" setting sends such links to the Windows browser. "Clear" in Settings and signing out give the panel a new profile and delete the old folder. `mailto` and `tel` go to Windows; `file:`, `javascript:`, `shell:`, executable files and other protocols are blocked, and so are automatic redirects of the main page to other sites. There is one exception, "Онлайн тест": after the student clicks it, the app waits 30 seconds for one server redirect to exactly `https://online-test.kaznu.kz` and opens it in the links panel (or in the Windows browser if "Open links in an external browser" is on), and the Univer page goes back to where the student left (`SitePolicy.OnlineTestExit`).

**Protects the window and the password with a PIN.** A 6-digit PIN (simple ones such as `123456` are refused) becomes a key through PBKDF2-SHA256 with 210,000 iterations and its own salt. This key encrypts a random data key, and the data key encrypts the saved login and password (AES-256-CBC and HMAC-SHA256). All of it is kept in `lock.dpapi` under DPAPI (`Core/AppLock.cs`). The login without the password is kept in `account.dpapi`, and `credentials.dpapi` is deleted: builds without the PIN read only that file and would send an empty password to the site. If `credentials.dpapi` cannot be deleted (another program holds it), the password stays in it, and every later unlock tries to delete the file again. Only saving a new account in Settings reports the failure; setting the PIN and unlocking go on silently. Until the PIN is entered, the app does not know the password and does not try to sign in. Next to it lies the `lock.pin` mark with no secrets. If `lock.dpapi` is deleted while the mark or `account.dpapi` remains, the next start deletes the saved account and replaces the browser profile, as signing out does. When the window is minimized, hidden in the tray or Windows is locked, the PIN screen covers it at once. If you come back after a minute or more, the app asks for the PIN; sooner than that, the cover goes away by itself. After errors the pauses grow (from 30 s to 30 min); after 10 errors the app signs out and deletes the saved password. The error counter is written before the PIN is checked.

**Signs out completely.** Signing out first records the pause of automatic sign-in, then cancels downloads, deletes the site's cookies and storage and creates a new browser profile. Sign out in Settings also erases the encrypted record; the sign-out link on the site itself keeps it. This is a sign-out on this computer: the app does not promise that the server ends all sessions and does not promise guaranteed erasure of files from the disk.

**What the app touches in Windows.** It reads (never writes) three registry keys: the Windows theme (`HKCU\…\Themes\Personalize`), font substitutes (`HKLM\…\FontSubstitutes`) and file preview handlers (`HKCR`). Ctrl+mouse wheel and the mouse's side buttons are caught with a hook on the thread of the app's own windows only (`UI/BrowserMouse.cs`), without global hooks or DLLs. Processes are started only on a user action: opening a downloaded file, the Downloads folder or an external link (`UI/MainForm.Actions.cs`, `UI/MainForm.Downloads.cs`). "Delete file" in Downloads, after you confirm, moves only that record's file to the Windows Recycle Bin, only on a local drive and only if its size is unchanged; the app never deletes files for good (`Core/FileDeletion.cs`).

## Test code in the sources

`UI/Qa/` contains the self-test (`--self-test`), which is also present in the normal build: it runs on synthetic pages with a separate temporary profile and never opens the real portal. The crawler of the real portal used for the owner's review (`UI/Qa/MainForm.Review.cs`, `MainForm.Explore.cs`, `MainForm.ReviewFeatures.cs`) is behind `#if QA_REVIEW` and is built only explicitly with `-p:QaReview=true`; it is not part of releases, and the normal build contains empty stubs in its place.

## Installer

The Inno Setup installer (`installer/Univer.iss`) installs the app for the current user without administrator rights. It downloads missing .NET Framework and Visual C++ only after you confirm and only from the addresses pinned in `installer/prerequisites.json` (`download.microsoft.com` and `download.visualstudio.microsoft.com`), checks the pinned SHA-256 and never restarts the computer by itself. During the build, the Inno Setup 7.1.0 compiler is downloaded by `scripts/prepare-installer-tools.ps1`, which checks its SHA-256 and publisher signature. The installer refuses to install into a folder with other files or into the user's data folder.

## Browser extension

- The manifest asks only for `storage` and access to `https://univer.kaznu.kz/*`: no `<all_urls>`, `tabs`, `cookies` or `downloads`, no remote code, the browser's default CSP. The build test `tests/dom/extension-build.test.cjs` checks this.
- The extension neither keeps nor types the password: the browser's password manager and the site's button sign in.
- The page scripts run in the extension's isolated world. Only `univer-automation.js` runs in the page's world, because it needs the site's jQuery and `agree()`. The bridge between the worlds carries strings and answers only five confirmation calls; there is no sign-in or reauthentication through it.
- The read notice and the agreement are confirmed only in the top frame, with the same exact selectors as in the app. Before the click the tab reserves an attempt with the extension's background: one send per form unless the page answers that it did not go out, and at most three notices and three agreements a minute across all tabs; an attempt the page answered for still counts. A tab showing an old copy of a form another tab has already sent never sends it. A form is freed only by a later page in the same tab or by that tab closing; of a closed tab the extension learns its number, not its address. If the reservation cannot be read, nothing is clicked, and no POST is sent again.
- «Download all» accepts only `https://univer.kaznu.kz/student/umkd/get/…` addresses, at most 200 files and 512 MB a file, and saves only a 200 answer from the same site; a sign-in page or an empty or truncated answer is dropped. A program or script is saved with `.bin` at the end of its name.
- The site's own script sees the same DOM and can forge a bridge message, as in the app. That gives no privileges: only pinning a section or sending a confirmation within the same budget.
- Until the extension is in the stores, a copy installed by hand from the ZIP does not update itself.

## Known limitations

- **Legacy contains known Chromium 109 vulnerabilities** ([GHSA-f87w-3j5w-v58p](https://github.com/advisories/GHSA-f87w-3j5w-v58p)); NuGet warns about them during the build (`NU1903`). It is needed only for Windows 7 SP1/8/8.1; on Windows 10/11 use Modern. The absence of known vulnerabilities in Modern on the release date does not mean there are none.
- **Files are not signed** with a publisher certificate. Compare the SHA-256 from the `.sha256` file next to each release file.
- **DPAPI does not protect against programs already running as you.** The encrypted record may end up in Windows profile backups; there is no guaranteed erasure from SSDs or backups. The password stays in the app's memory while it is needed for sign-in.
- The site's own pages may load resources from other servers, as in any browser; the app does not add them.
- **A PIN does not protect against programs running as you.** Such a program can read `lock.dpapi` and try a million PINs on its own, without the error counter: the Windows version has no hardware key like a phone. The PIN does not encrypt the site's cookies in the browser profile: whoever deletes `lock.dpapi`, `lock.pin` and `account.dpapi` opens the app with the old site session, but without the saved password. The decrypted password stays in memory until the app closes. The lock time cannot be changed (one minute), and there is no sign-in through Windows Hello.
- **Updates come from GitHub.** The app downloads an installer only from `github.com` and `*.githubusercontent.com` over HTTPS, and only after you press Install. While files are unsigned, the SHA-256 from the same release protects against a damaged file, not against a replaced release. A signed version accepts only a file from the same publisher.

## Checking it yourself

All sources are in this repository; the build is described in [BUILD.en.md](BUILD.en.md). The app's network code is Chromium (the site's pages) and two `HttpClient`s: in `Web/SessionHttp.cs` for downloads and in `Core/UpdateClient.cs` for updates; searching `src/` for `HttpClient`, `WebRequest`, `Process.Start`, `Registry.` and `SetWindowsHookEx` shows every such place. Other addresses appear in the code only in the self-test's synthetic pages (a copy of the site's "Useful links") and as XML namespace names in Office documents. Privacy and stored data: [PRIVACY.en.md](PRIVACY.en.md).

If settings are missing, damaged or temporarily unreadable, the saved password remains encrypted and automatic sign-in waits for an explicit "Sign in again". A settings read error cannot undo a previous sign-out.
