# Безопасность

## Как сообщить об уязвимости

Пишите закрытым сообщением через вкладку **Security → Report a vulnerability** этого репозитория. Не публикуйте подробности в открытых issues, пока исправление не вышло. Опишите версию и вариант (Modern или Legacy, x64 или x86), шаги и что должно было произойти. Не присылайте пароли, cookies и снимки чужого кабинета.

Исправления выходят только для последней версии. Вариант Legacy построен на Chromium 109, для которого обновлений безопасности больше нет (подробно ниже): уязвимости самого Chromium в нём исправить нельзя.

## Что приложение делает

**Работает только с одним сайтом.** Автоматизация, сохранённый пароль, cookies сессии и защищённые скачивания допускаются только для точного адреса `https://univer.kaznu.kz` (порт 443, без логина в адресе). HTTP, другие порты, поддомены и похожие адреса их не получают. Правило в `src/Univer.Desktop/Core/SitePolicy.cs`. Встроенные фреймы других сайтов не получают ни данных входа, ни скриптов приложения.

**Проверку HTTPS не ослабляет.** Сертификаты проверяет Chromium и Windows; `ignore-certificate-errors` и «доверять всем» не используются, ошибки сертификата отклоняются. Legacy запускает Chromium 109 с `disable-features=ChromeRootStoreUsed`: его встроенный список корневых сертификатов устарел и не принимает текущую цепочку сайта, поэтому используется проверка и хранилище сертификатов Windows. Проверка цепочки, имени и срока при этом остаётся.

**Хранит пароль зашифрованным.** Логин и пароль хранятся одной записью `credentials.dpapi`, зашифрованной Windows DPAPI для текущего пользователя (`ProtectedData`, `CurrentUser`), файл заменяется атомарно (`Core/Storage.cs`). Пароля нет в исходниках, настройках, журналах и в папке программы. Журналы Chromium отключены.

**Входит через форму самого сайта.** На `/user/login` приложение заполняет видимые поля логина и пароля и нажимает кнопку сайта; собственного HTTP-входа и обхода скриптов сайта нет. Окно повторного входа сайта (`#auth_modal`) подтверждается его же запросом `/user/ajl`, и результат проверяется по ответу сервера. Если сайт спрашивает пароль другого аккаунта, приложение останавливается, не вводя пароль. Попытки ограничены: не больше трёх отправок формы входа за 10 минут и трёх повторных входов в минуту; после двух отказов формы подряд автовход останавливается до действия пользователя. Отправка формы (POST) никогда не повторяется автоматически; при сбое сети перезагружается только страница (GET) с растущей паузой от 5 секунд до 5 минут.

**Подтверждает только два известных окна.** При сохранённом входе приложение отмечает флажок и нажимает кнопку сайта в двух окнах, которые закрывают кабинет после входа: уведомление о прочтении (`#attentionSt`) и дополнительное соглашение (`#modal_agreement`, флажок «прочитал договор», `/user/setagree`). Каждое окно распознаётся по точной разметке и подписи, подтверждается один раз, без повторной отправки. Других форм, анкет, сообщений, заявок и оплат приложение не отправляет и не подтверждает. Код в `src/Univer.Desktop/Assets/univer-automation.js` и `Web/AutomationController.cs`.

**Читает страницы в фоне только через GET.** Уведомления (`Assets/notices.js`) и задания «Дистанционных курсов» (`Assets/course-tasks.js`) читают страницы того же сайта запросом `fetch` с cookies сайта, только GET, с ограничением по времени и размеру. Ответ с другого адреса, не HTML или страница входа отбрасывается. Ничего не нажимается и не отправляется.

**Не даёт страницам доступа к компьютеру.** Объектов с доступом к файлам или системе в JavaScript нет. Страница может только отправить приложению короткие сообщения (состояние загрузки, язык, результат входа), и они принимаются только из главного документа доверенного сайта и текущей сессии. Порт удалённой отладки Chromium не открывается.

**Проверяет скачивания.** Файлы УМКД скачивает отдельный клиент (`Web/DownloadService.cs`, `Web/SessionHttp.cs`): cookies отправляются только сайту, не больше пяти переадресаций и только внутри сайта, только ответ 200, страница входа или HTML вместо файла отклоняются, файл до 1 ГБ. Имя файла очищается от недопустимых символов и путей, существующий файл не перезаписывается, недокачанный `.part` удаляется. Файлы сохраняются в папку «Загрузки» и сами не открываются: документ или картинку открывает только ваше нажатие, а EXE, CMD и другие исполняемые файлы приложение не запускает.

**Показывает файлы без их программ.** Просмотр DOC, DOCX, XLS, XLSX, PPT, PPTX, HTML и текста строит собственную разметку из содержимого файла (`Core/*Html.cs`, `Core/HtmlPreview.cs`). Страница просмотра отдаётся с правилом CSP `default-src 'none'`: без скриптов, фреймов и сети. XML читается без DTD и внешних сущностей, размеры и глубина ограничены. HTML перестраивается по белому списку: скрипты, стили, формы, обработчики и внешние картинки удаляются. PDF показывает Mozilla PDF.js из папки программы.

**Открывает внешние ссылки в браузере Windows.** Разрешены только `http`, `https`, `mailto` и `tel`; `file:`, `javascript:`, `shell:`, исполняемые файлы и другие протоколы блокируются, автоматические переходы главной страницы на другие сайты тоже.

**Выходит полностью.** Выход сначала записывает остановку автовхода, затем отменяет загрузки, удаляет cookies и хранилище сайта и создаёт новый профиль браузера. Удаление данных входа стирает зашифрованную запись. Это выход на этом компьютере: приложение не обещает, что сервер завершит все сессии, и не обещает гарантированного стирания файлов с диска.

**Что приложение трогает в Windows.** Читает (без записи) три ветки реестра: тему Windows (`HKCU\…\Themes\Personalize`), подстановки шрифтов (`HKLM\…\FontSubstitutes`) и обработчики предпросмотра файлов (`HKCR`). Ctrl+колесо мыши перехватывается хуком только своего потока (`UI/CtrlWheel.cs`), без глобальных хуков и DLL. Процессы запускаются только по действию пользователя: открыть скачанный файл, папку «Загрузки» или внешнюю ссылку (`UI/MainForm.Actions.cs`, `UI/MainForm.Downloads.cs`).

## Проверочный код в исходниках

`UI/Qa/` содержит самопроверку (`--self-test`), которая есть и в обычной сборке: она работает на синтетических страницах с временным отдельным профилем и не открывает настоящий кабинет. Обходчик настоящего кабинета для ревью владельцем (`UI/Qa/MainForm.Review.cs`, `MainForm.Explore.cs`, `MainForm.ReviewFeatures.cs`) закрыт условием `#if QA_REVIEW` и собирается только явно с `-p:QaReview=true`; в выпуски он не входит, в обычной сборке на его месте пустые заглушки.

## Установщик

Установщик Inno Setup (`installer/Univer.iss`) ставит приложение для текущего пользователя без прав администратора. Недостающие .NET Framework и Visual C++ он скачивает только после подтверждения и только с адресов, закреплённых в `installer/prerequisites.json` (`download.microsoft.com` и `download.visualstudio.microsoft.com`), проверяет закреплённую SHA-256 и не перезагружает компьютер сам. Компилятор Inno Setup 7.1.0 при сборке скачивается скриптом `scripts/prepare-installer-tools.ps1` с проверкой SHA-256 и подписи издателя. Установщик отказывается ставить в папку с чужими файлами и в папку данных пользователя.

## Известные ограничения

- **Legacy содержит известные уязвимости Chromium 109** ([GHSA-f87w-3j5w-v58p](https://github.com/advisories/GHSA-f87w-3j5w-v58p)), NuGet при сборке предупреждает о них (`NU1903`). Он нужен только для Windows 7 SP1/8/8.1; на Windows 10/11 используйте Modern. Отсутствие известных уязвимостей в Modern на дату выпуска не значит, что их нет.
- **Файлы не подписаны** сертификатом издателя. Сверяйте SHA-256 из файла `.sha256` рядом с файлом выпуска.
- **DPAPI не защищает от программ, уже работающих от вашего имени.** Зашифрованная запись может попасть в резервные копии профиля Windows; гарантированного стирания с SSD и из копий нет. Пароль в памяти приложения хранится, пока он нужен для входа.
- Страницы самого сайта могут загружать ресурсы с других серверов, как в обычном браузере; приложение их не добавляет.
- Автообновления нет: о новых версиях узнавайте на странице выпусков.

## Как проверить самому

Исходники полностью в этом репозитории, сборка описана в [BUILD.md](BUILD.md). Сетевой код приложения: Chromium (страницы сайта) и один `HttpClient` в `Web/SessionHttp.cs` для скачиваний; поиск по `HttpClient`, `WebRequest`, `Process.Start`, `Registry.` и `SetWindowsHookEx` в `src/` покажет все такие места. Другие адреса в коде встречаются только в синтетических страницах самопроверки (копия «Полезных ссылок» сайта) и как имена пространств XML в документах Office. Приватность и хранимые данные: [PRIVACY.md](PRIVACY.md).
